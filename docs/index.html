01what it is

Three verbs, and a grammar appears.

There is no grammar file and no generator: a grammar is MoonBit code that builds parsers, and the compiler checks it like any other code. Reading, composing and refusing are the whole vocabulary.

read

Characters, runs of them, or a literal.

let word = @moonpsec.string("let")
let answer = @moonpsec.run(word, "let")

answer is Ok("let")

compose

Two parsers in order, one value kept.

let both = @moonpsec.digit
  .then(@moonpsec.digit)
let one = @moonpsec.run(both, "12")

then keeps the second; one is Ok('2').

refuse

A refusal carries where, what, and what would have done.

let digit = @moonpsec.digit
let bad = @moonpsec.run(digit, "x")
let why = bad.unwrap_err().to_string()

1:1 unexpected 'x'; expecting digit

02the rule

A choice is not a search.

Once a branch has read a character it has committed to its reading. A later mistake is reported, not quietly retried another way. That one rule is what makes a grammar predictable — and attempt is how a grammar asks for the other branch anyway. 

let committed = @moonpsec.string("ab").or(@moonpsec.string("ac"))
let retried = @moonpsec.string("ab").attempt().or(@moonpsec.string("ac"))

run(committed, "ac") — refused at 1:2, expecting "ab".

run(retried, "ac") — Ok("ac"), because the first branch left the text where it found it.

03expectations

Every alternative, at one place.

When both branches of a choice stop at the same character, the refusals merge: what each would have accepted is kept, sorted, and said in one sentence. A reader never has to fix one alternative to discover the next.

label replaces the character classes with the word a reader needs — expecting integer instead of expecting digit — and hidden takes the expectations away for a branch that exists only to be tried. 
let integer = @moonpsec.digit.many1().label("integer")
let refusal = @moonpsec.run(integer, "x").unwrap_err()

1:1: unexpected 'x'; expecting integer

04the table

Precedence is a list, not a cascade of functions.

An expression grammar is a term parser and a table of operators, ordered from the tightest binding to the loosest. Left, right and non-associative operators, prefix and postfix, and a right-associative conditional are entries in that table. 

let number = @moonpsec.take_while1(ch => ch.is_ascii_digit()).map(text => {
  let mut value = 0
  for index in 0..<text.length() {
    value = value * 10 + (text.unsafe_get(index).to_int() - '0'.to_int())
  }
  value
})
let times = @moonpsec.char('*').map(_ => (a : Int, b : Int) => a * b)
let plus = @moonpsec.char('+').map(_ => (a : Int, b : Int) => a + b)
let table : Array[Array[@moonpsec.Operator[Int]]] = [
  [@moonpsec.Operator::InfixL(times)],
  [@moonpsec.Operator::InfixL(plus)],
]
let expression = @moonpsec.make_expr_parser(number, table)

run(expression, "2+3*4") is Ok(14). See it drawn, in play.

05arriving

Text that is not all here yet.

A feeder takes the text a chunk at a time. When the text ends in the middle of something it says so, and the parser is run again when the rest arrives — the grammar never learns that its text came in pieces. 

let hello = @moonpsec.string("hello").eof()
let feeder = @moonpsec.feeder(hello)
let first = feeder.feed("he")

first is Needs(1); second is Ready("hello") once the text ends. feeder.finish() is the end of the text.
