The document is read from the left. Every character up to the trailing comma is accepted; at the closing brace the reader refuses, because a comma cannot be followed by the end of an object.

01position

A position is three numbers.

An offset into the text, a line, and a column. Every step carries them forward. A tab moves to the next stop — with the default width of eight, a tab at the start of a line puts the next character in column 9 — and a character above the basic plane counts once, the way a reader counts it, not the way a machine stores it.

The position is not a side effect of reading; it is an answer. position is a parser like any other, so a grammar can return where it got to.

02expecting

One place, every alternative.

When a choice fails, the last branch tried is not the one that speaks. Every branch that failed at the same place contributes its expectation, and the message names them together: one position, one sentence, all the alternatives.

label does not hide them. It replaces the character classes of one branch with the reader's word for it, which is what a person reading the message needs.

03commit

A branch that has read something has committed.

Once a parser has consumed a character, a later or will not undo it: the text has been read, and the failure is about what comes next. That is what keeps a grammar from trying every alternative at every offset.

attempt is how a grammar says the opposite — give the character back, and let the other branch have it.

Every parser stops somewhere. The only question is what it can tell you when it does.

04pieces

The text does not have to arrive all at once.

A feeder takes the text in chunks and answers Needs while the end of what it has is still in the middle of something. Feed the rest and the same grammar finishes the job — no second parser, and nothing that was settled is read twice.

The document at the top of this page is read that way: held short at every character, and asked what it would say if the text ended there.
